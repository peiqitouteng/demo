主流程：想法 → 交付

大多数工作走这条路。步骤 1–3 请留在同一个上下文窗口里，别压缩、别清空，直到 /to-tickets 跑完。

    两个分叉，一句话记住

    • 要跑起来才知道？ 用 /handoff 绕到 /prototype，再把结论 handoff 回来。
    • 装不进一个会话？ /to-spec → /to-tickets，然后每张工单开一个新会话跑 /implement。

    命令速查

    每个技能一条：打 /名称 就能用。你调用的技能必须由你输入命令触发； 模型调用的技能 agent 会自己取用，你也可以直接点名。按 / 聚焦搜索。

    没有匹配的技能。换个关键词，或点「全部」看完整清单。

    入口、健康与阶段边界

    主线之外的三处补充：活从哪儿冒出来、代码库怎么保养、一个阶段结束时的五种选择。

    两个入口

    • /triage bug 报告与功能请求堆积时。只处理不是你创建的原始输入。
    • /diagnosing-bugs 坏了、而且一眼看不出原因。先有一条变红的命令，再谈理论。
    • /wayfinder 大到装不进一个会话、路线还看不清的工程。产出决策，路清后回 /to-spec。

    代码库健康

    • /improve-codebase-architecture 有空就做：扫出「深化机会」，出一份 HTML 报告，再拷问你挑中的那个。

    词汇层

    • /domain-modeling 领域语言的纪律：术语、一词多义、ADR、CONTEXT.md。
    • /codebase-design 深模块的词汇：module、interface、depth、seam、adapter、leverage、locality。

    阶段边界：五种选择

      在边界上做决定。阶段中途？要么继续，要么把剩下的活拆给子代理。
